# Miracle Habesha Shop

A polished demo storefront for an Eritrean & Ethiopian cultural food shop in Nørrebro, Copenhagen. Built as a production-shaped Next.js frontend that can later be connected to Lovely Loyalty POS.

Danish is the default language, with English and DKK/EUR/SEK currency switching throughout.

## Run locally

Requires Node.js 20.9 or newer.

```bash
npm install
npm run dev
```

Open http://localhost:3000. The Danish storefront is served at `/`; English at `/en`.

```bash
npm run lint
npm run build
npm run start
```

## What is included

- Editorial home page, category browsing, search, filters and sorting
- 29 demo products with variants, stock levels, allergens, heat levels and related items
- Product pages with gallery, points earned, quantity and add-to-cart
- Persistent cart, free-shipping progress, checkout and order confirmation
- Loyalty account with tier progress, points ledger, local orders and rewards redemption
- Demo Lovely Loyalty POS integration page plus mock API endpoints and webhook log
- About, delivery, returns, FAQ, terms and privacy pages
- Localized metadata, product JSON-LD, sitemap, robots and a custom 404

All commerce state is client-side (Zustand + localStorage). There is no real payment, authentication, inventory reservation or order fulfillment.

## Languages and currency

- Locales: `da` (default) and `en`
- Danish URLs have no prefix (`/shop`), English uses `/en/shop`
- Locale detection is deliberately disabled so the Danish storefront is always the entry point
- Currencies: DKK, EUR, SEK with approximate fixed demo rates (EUR 0.134, SEK 1.53)
- All money is stored as integer øre and formatted with `Intl.NumberFormat`

Copy lives in `messages/da.json` and `messages/en.json`. Keep both files in sync when adding strings.

## Demo data and rules

- Demo member: Fatima Hassan, Harvest tier, 1,240 points
- 1 point per 10 DKK spent
- 200 points can be redeemed for 20 DKK at checkout
- Free shipping from 499 DKK; home delivery is 49 DKK below the threshold
- Pickup in store is free

Data is seeded in:

- `src/data/products.ts`
- `src/data/categories.ts`
- `src/data/member.ts`
- `src/data/rewards.ts`
- `src/data/info.ts`

Client state lives in `src/store/`. Persisted stores use `skipHydration` and are rehydrated by `StoreHydrator`; gate cart, checkout and loyalty UI with `useStoreHydrated()`.

## Lovely Loyalty POS adapter

The storefront talks to POS through a small interface instead of importing mock data directly:

```ts
// src/lib/pos/types.ts
export interface PosAdapter {
  readonly provider: string;
  readonly mode: "mock" | "live";
  getCatalog(locale: Locale): Promise<Product[]>;
  getInventory(): Promise<InventorySnapshot[]>;
  getMember(memberId?: string): Promise<LoyaltyMember>;
  getPointsHistory(memberId: string): Promise<PointsTransaction[]>;
  getRewards(): Promise<Reward[]>;
  getSyncState(): Promise<PosSyncState>;
  getWebhookEvents(): Promise<PosWebhookEvent[]>;
  sync(): Promise<PosSyncState>;
}
```

`src/lib/pos/index.ts` currently exports a `MockPosClient`. To go live, implement the same interface against the Lovely API and swap the exported instance. Nothing in the UI needs to change.

Demo endpoints:

- `GET /api/pos/catalog`
- `GET /api/pos/member`
- `GET|POST /api/pos/sync`

The integration page at `/integrations/lovely` shows sync state, webhook events and inventory from the adapter.

## Branding assets

- Brand tokens, fonts and ornament styles: `src/app/globals.css` and `src/components/brand/`
- The header/footer currently use the SVG `BrandSeal` placeholder
- To use the real logo, add `public/brand/logo.png` and update `BrandLockup` in `src/components/brand/logo.tsx`
- Category and editorial imagery lives in `public/images/`
- Product packaging art is generated by `src/components/brand/product-art.tsx`

## Project structure

```text
src/
  app/[locale]/          pages, metadata, sitemap, robots, 404
  app/api/pos/           mock POS endpoints
  components/            layout, shop, product, cart, checkout, loyalty
  components/ui/         shadcn/Base UI primitives
  data/                  demo catalog, member, rewards, help content
  i18n/                  routing, navigation and request config
  lib/                   currency, catalog helpers, POS adapter, types
  store/                 Zustand cart, orders, loyalty, preferences
messages/                Danish and English copy
public/                  images and brand assets
```

Next.js 16 specifics used here: `src/proxy.ts` for locale routing, async `params`/`searchParams`, and Turbopack. See `node_modules/next/dist/docs/` before changing framework-level code.

## Deploy

The app deploys unchanged to Vercel:

```bash
npm run build
```

Set the project root to this directory and use the default Next.js build settings. No environment variables are required for the demo. Add POS credentials as server-only environment variables when implementing the live adapter.

## Notes

- This is a demo frontend. Do not treat stock, orders, points or webhook events as real records.
- Demo orders are stored locally and shown in the account area.
- External product photography is loaded from `public/images/`; review licensing before a public launch.
